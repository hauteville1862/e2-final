## 2. 작업 방식 (합의된 규칙)

1. **코드는 사용자가 직접 작성한다.** 미션.md의 요구사항 순서대로 사용자가 코드를 붙여넣으면, 검토·테스트하고 커밋한다. 사용자가 명시적으로 요청할 때만 코드를 대신 수정한다.
2. **커밋 전 승인을 받는다.** 커밋 메시지와 대상 파일을 구분선으로 분리한 별도 블록으로 제시하고, 승인 후에만 `git commit` / `git push`를 실행한다.
3. **질문은 한 번에 하나씩** 제시한다.
4. **커밋 메시지 접두사는 6종만** 사용한다 — `Feat` / `Fix` / `Docs` / `Refactor` / `Chore` / `Test`. 본문은 한국어로 작업 내용이 드러나게 쓴다. (미션.md:275 근거, 평가 2-5 대응)

### 5-2. 환경 관련 주의사항

**push는 PowerShell에서 해야 한다.** WSL에는 GitHub 자격 증명이 없어 인증 실패한다. GitHub는 비밀번호 인증을 지원하지 않으므로 WSL에서 하려면 토큰이나 SSH 키를 따로 설정해야 한다.

**WSL에서 `git checkout`이 실패하는 문제.** Windows Git은 `core.autocrlf=true`라 작업 폴더 파일이 CRLF 줄바꿈이다. WSL Git에는 그 설정이 없어 모든 파일을 "수정됨"으로 인식한다. 해결하려면 WSL에서 `git config --global core.autocrlf input`을 실행한다. 또는 그냥 PowerShell을 쓴다.

**`git log`가 반복 출력되는 것처럼 보이는 현상**은 페이저(`less`) 때문이다. `q`로 빠져나오고, 스크린샷을 찍을 때는 `git --no-pager log --oneline --graph`를 쓴다.

### 5-3. 브랜치

- `main` — 기본 브랜치
- `feature/quiz_game` — 6단계 작업용. 병합 완료. **삭제하지 말 것** (평가 1-6 확인 자료)

병합은 `git checkout main` 후 `git merge feature/quiz_game --no-edit`으로 수행했다. `--no-edit`은 편집기(vim)가 열리는 것을 막는다.

### 5-4. 커밋을 단계별로 나누는 방법

한 파일에 여러 단계 분량이 들어와 있을 때, 해당 단계 부분만 남기고 나머지를 잠시 덜어낸 뒤 커밋하고 곧바로 복원했다. 덜어낸 코드는 스크래치패드에 백업해두었다. 이 방식으로 `storage.py`를 5단계(기본 데이터)와 11단계(load/save)로 나누었다.

## 6. 알려진 문제 (미해결)

### 6-1. 퀴즈 목록이 정답을 노출한다 — 8단계에서 수정

`view_question_list`가 `(정답: 1번)`을 함께 출력한다. 목록을 보고 답을 다 알 수 있어 게임이 성립하지 않는다. 미션 예시(미션.md:354–355)도 지문만 보여준다.

### 6-2. 아직 퀴즈를 풀지 않은 경우 처리 없음 — 9단계에서 수정

`show_high_score`가 기록이 없어도 "최고 기록은 0점입니다"를 출력한다. 미션.md:173이 요구하는 처리다.

### 6-3. 저장 실패를 알리지 않는다 — 7단계에서 판단

`add_new_question`이 `save()`의 반환값을 확인하지 않아, 저장이 실패해도 "성공적으로 추가되었습니다"가 출력된다. `save()`는 실패 시 `False`를 반환하도록 구현되어 있다.

### 6-4. state.json 경로가 실행 위치에 따라 달라진다 — 사용자 판단으로 보류

`Storage.__init__`의 `path="state.json"`이 상대 경로라 현재 작업 디렉터리 기준으로 열린다. 다른 폴더에서 실행하면 엉뚱한 곳에 파일이 생긴다. 미션은 "프로젝트 루트의 state.json"을 요구한다(미션.md:44, 263). 고치려면 `Path(__file__).resolve().parent / "state.json"`을 쓴다.

### 6-5. JSON이 딕셔너리가 아니면 TypeError — 사용자 판단으로 보류

`state.json`에 `5`처럼 값 하나만 들어 있으면 `"high_score" not in data`에서 `TypeError`가 발생해 복구 경로를 타지 못한다. `except (ValueError, TypeError)`로 넓히거나 `isinstance(data, dict)` 검사를 추가하면 해결된다.

### 6-6. Ctrl+C 시 저장하지 않는다 — 11단계에서 판단

미션.md:123은 "가능한 범위에서 저장 후 안전하게 종료"를 요구한다. 현재 `main.py`의 `except` 블록은 안내만 하고 종료한다. 퀴즈 도중 중단하면 그때까지의 점수가 사라진다.

## 7. 설명 준비 (평가 대비)

### 7-1. 클래스를 쓴 이유 (평가 3-1)

핵심 문장: **"문제에 관한 일은 문제 자신이 한다."**

리팩터링 전에는 `quiz_cli.py`가 `current_question.question`, `.choices`를 직접 꺼내 출력했고, `quiz_game.py`가 `.answer`를 직접 비교했다. 문제의 내부 구조를 바깥 두 곳이 알고 있던 셈이다.

지금은 `Quiz.show(번호)`와 `Quiz.is_correct(답)`을 호출한다. 바깥에서는 내부 구조를 몰라도 된다.

함수만으로 만들었다면 `show_quiz(question, choices)`처럼 매번 데이터를 넘겨야 하고, 문제가 여러 개일 때 지문·선택지·정답의 짝이 어긋나지 않도록 따로 관리해야 한다.

### 7-2. 예외를 진입점에서 잡은 이유 (평가 2-4)

`Ctrl+C`는 프로그램 어디서든 발생할 수 있다. `input()`마다 처리를 넣으면 같은 코드가 흩어진다. 파이썬은 예외를 처리하는 곳을 만날 때까지 호출한 함수를 거슬러 올라가므로, 진입점에서 한 번 잡으면 어디서 발생하든 그곳으로 온다.

`except Exception`으로 전부 잡지 않은 이유: 오타로 인한 `NameError` 같은 진짜 버그까지 삼켜서 문제를 발견하지 못하게 된다.

`sys.exit(0)`의 0은 정상 종료를 뜻하는 종료 코드다. 의도한 대로 처리하고 끝냈으므로 오류가 아니다.

### 7-3. 부모 클래스 하나로 여러 예외 잡기 (평가 3-3)

- `load()`의 `except ValueError` — `json.JSONDecodeError`가 `ValueError`의 하위 클래스라 자동으로 걸린다. 여기에 더해 키가 누락된 경우를 직접 `ValueError`로 던져서, "문법은 맞지만 내용이 잘못된 파일"까지 같은 경로로 처리한다.
- `save()`의 `except OSError` — `PermissionError`, 디스크 가득 참, 경로 사라짐 등이 모두 `OSError`의 하위 클래스다.

`load()`는 실패해도 기본 데이터로 복구할 수 있지만 `save()`는 복구할 방법이 없다. 그래서 `load()`는 조용히 회복하고 `save()`는 사용자에게 알린다.

### 7-4. 브랜치와 병합 (평가 3-4)

`feature/quiz_game`에서 6단계를 작업하는 동안 `main`에는 문서 커밋이 따로 쌓였다. 두 갈래가 갈라진 상태를 `git_log_graph_before_merge.png`가 보여준다.

병합 커밋은 **부모가 둘**이다(`65cea0e`와 `c216597`). 그래서 그래프에 다이아몬드 모양이 생긴다. 합침 자체가 커밋으로 기록되어 무엇이 언제 합쳐졌는지 이력에 남는다.

### 7-5. 채점 순서가 중요한 이유 (평가 1-2)

`QuizGame.submit_answer`는 정답 판정을 **먼저 하고** `question_number`를 증가시킨다. 순서가 반대면 다음 문제의 정답과 비교하게 되어 채점이 전부 틀어진다.

### 7-6. 입력 검증을 분리한 이유 (평가 2-2)

`get_valid_int(prompt, min, max)` 하나를 메뉴 선택(1~5)과 정답 입력(1~4) 양쪽에서 재사용한다. 범위만 인자로 바꾼다. 7단계의 정답 번호 입력에서도 같은 함수를 쓴다.

## 8. 검증 방법

프로그램에 입력을 미리 넣어 자동으로 확인할 수 있다.

```bash
# 퀴즈 풀기 후 종료 (1번 선택 → 답 5개 → 엔터 → 5번 종료)
printf '1\n1\n2\n2\n4\n1\n\n5\n' | python main.py

# 잘못된 입력 처리 확인
printf ' 1 \nabc\n9\n\n5\n' | python main.py

# EOF 안전 종료 확인
python main.py < /dev/null
```

한글이 깨져 보이면 `PYTHONIOENCODING=utf-8`을 앞에 붙인다.

**손상 파일 복구 확인**
```bash
echo '{broken' > state.json && python main.py
```

**퀴즈 없는 경우 확인**
```bash
echo '{"high_score": 0, "questions": []}' > state.json && python main.py
```
